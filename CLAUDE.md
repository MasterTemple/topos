# topos

Finds and parses Bible references in text and documents, reporting where each one is in the source's own terms. See `ROADMAP.md` (what's done and planned) and `doc/architecture.md` (design). `doc/review.md` is a historical snapshot; most of it is fixed.

## Crates

Crates are named by package (folder in parentheses); `topos-bible`, `topos-bible-formats`, `topos-bible-index`, and `topos-bible-cli` are published to crates.io, the others are `publish = false`.

- `topos-bible` (`crates/topos-lib`, core, no native deps; its README is the crate docs and its examples are doc tests). Pipeline: book candidates → `segments::grammar` (lexer and parser that never fails, lossless `SegmentList` with byte spans) → `segments::resolve` (what numbers mean, plus versification checks) → filter → `LineColLocation`.
  - `BibleMatcher::search(text)`, `complete(text, cursor, opts)` (returns `TextEdit`s), `problems(text)` (references that don't exist)
  - `FormatOptions` (formatting; serde with every field optional and unknown fields rejected, which the CLI's `--psg-fmt`/`--fmt-*` and the FFI's `ToposFormat` use), `segments::osis` (OSIS and BCV keys), `data::translations` (`Translations`: names, aliases, and each translation's own chapter and verse counts; read only by `BibleData::parse_with_translation`, `BibleMatcher::search_with_translations`, `problems_with_translations`, and `complete_with_translations`, which return new types like `TranslatedPassage` and `TranslatedMatch` so `Passage` and `BibleMatch` stay small; cases in `tests/cases/translations.txt`, run by the library and the FFI; plan in `doc/translations.md`), `matcher::context` (bare `1:1` references with a book context)
- `topos-bible-markup` (`crates/topos-markup`, not yet published): Bible markup (OSIS, ThML, GBF, TEI, USX, plain text) parsed into one tolerant tree (`Node`, `Element`, `Kind`; parsing never fails). `Filter` keeps, unwraps, or drops elements (by kind, note type, or rule); `Flattener` makes a `Flat` (plain text, a map back to tree paths, and a span per element), which plain text, search, and editor highlighting share; `TextOptions::verse_label`/`chapter_label` write templates (`[{verse}]`) at markers, `TextOptions::templates` writes `{text}` templates around elements (`“{text}”`, glued to the words; notes default to `[{text}]`), and `Flat::entries` gives each pushed entry's range; `HtmlRenderer` writes classes with a prefix (default `topos-`; data attributes are never prefixed) and `wrap` puts a passage in `<div class="topos">`; `mark(start, end)` wraps a `MarkupLocation`'s range in `<mark class="topos-mark" data-mark="n">` (entries count render calls, like `Flattener::push`). Class names are API (listed on `HtmlRenderer`). `refs::tagged_references` reads the references the markup tags. `verses::verses` finds each verse in a whole book (from the end of the verse before, so headings go with the next verse), `verses::slice` copies the tree between two places, and `verses::passage_ranges` maps a `Passage` to verses (checked on the whole BSB in USX). Moved from sword-modules (which depends on it); `cargo run --release -p topos-bible-markup --example fuzz` must not panic.
- `topos-bible-formats` (`crates/topos-formats`): the `Format` trait / `search_format::<L>()` for html, srt (also WebVTT and SBV), epub, json, xml, markup (feature `markup`: `MarkupLocation`, searching a `Flat`), and pdf (feature `pdf`, MuPDF 0.8). `htmloc` (text fragments) is a module here, formerly a git dependency.
- `topos-bible-index` (`crates/topos-index`): a persistent index of many files' references (`Index`): compact entries (`FileEntry`, references in a hand-written codec, `codec.rs`), checks for changed files (size and mtime, else a content hash or size after syncing), per-device `Pack`s (32 per device, uncompressed postcard) so syncing never conflicts, EPUB `Detail`s (CFIs and ~200-character snippets, deflate) read on demand, and filtered, sorted, paged queries (each order cached until the index changes). The CLI's `-m index` writes its entries; the FFI exposes it as `ToposIndex`. Feature `files` (native): searching files and folders as the CLI does, shared by the CLI, LSP, and FFI: `files::WalkOptions` (ripgrep's options through `ignore`), `files::search`/`search_file` (formats), and `files::Cache` (per-file postcard entries with a books bitset, in `default_root()` or any folder).
- `topos-bible-cli` (`crates/topos-cli`): binary `topos`. Paths are positional; text comes from `--text` or piped stdin. Default options come from `~/.config/topos/config.toml` (`--config PATH` reads another file, `--no-config` skips it). Passage filters: `-i/--inside`, `--any-overlap` (old `--overlaps`), `-o/--explicit-overlap` (whole chapters in a reference don't count), `--exact-overlap`, and `--exclude-overlap` (old `--outside`); the config reader accepts the old names. `--data` takes custom Bible data JSON. Path options mirror ripgrep's (`--hidden`, `--no-ignore*`, `-u`, `--glob`, `--max-depth`, `--files`, `-l`) and map to the library's `files::WalkOptions`; `.toposignore` files are respected. `--cache` is opt-in and uses `files::Cache` (unfiltered results, filtered per search with `BibleMatcher::keeps`); `tests/unfiltered.rs` checks that equals a filtered search. The CLI itself is arguments (`args.rs`), stdin (`input.rs`), and output (`output.rs`).
- `topos-lsp`: completion, hover, inlay hints, document symbols, diagnostics, go-to-references (exact overlap across the workspace), and code actions that run the `topos.search` command (`lsp-server` 0.10). Settings come from the CLI's `config.toml`, overridden by the editor's (`settings.rs`); workspace files are walked with `ignore` (`workspace.rs`). It caches each workspace file's references in memory (unfiltered, keyed by size and mtime). With `bible` (a folder of USX files) and `markup` (`bible.rs`): passage text in hover, go-to-definition into a whole book (`topos-bible://BSB/JHN`, text from the `topos/book` request, colored by semantic tokens), references from a verse in it (explicit overlap), and hover on a verse counting them (with a deadline, `???` past it). `insertions` are code actions that insert a passage with their own markup. Hover and completion documentation (`completionItem/resolve`) write passages as ```` ```topos-bible ```` code blocks whose info string lists tokens (`line:col:len:type`), which the Neovim plugin colors. A book is flattened in one pass (cutting it per verse splits paragraphs) and its verses found from their markers.
- The Neovim plugin moved to its own repository, `~/Development/nvim-plugins/topos-bible.nvim` (October 2026; it was `lua/`, `plugin/`, `doc/topos-bible.txt`, `tests/nvim/` here). Its `:ToposBuild` runs `cargo install` from GitHub or a checkout (`source`), and its tests (`tests/nvim/run.sh`) build `topos-lsp` and `topos-bible-cli` from `TOPOS` (default `../../rust/topos`, this checkout), so keep those crate paths stable. It runs topos-lsp, opens `topos-bible://` books, handles `topos.search`, and searches with the CLI (`topos -m json`).
- The Obsidian plugin moved to its own repository, `~/Development/typescript/obsidian-topos-bible` (October 2026; it was `obsidian/`). It builds against this checkout's WASM package (`crates/topos-ffi/dist/wasm/pkg`) and its tests read `complete.txt` and run `target/debug/topos`, so keep those paths stable. topos only finds and parses references; Bible text and rendering for the plugin don't belong in `topos-bible`.
- `topos-ffi`: the BoltFFI 0.31 façade (its library is `topos_bible` for the packages, so it depends on the core as `topos_lib`), the only bindings crate. Offsets are in the caller's unit (byte, char, UTF-16). `Topos.searchFiles`/`listFiles` with `ToposFiles` (the CLI's walking options and cache, `cacheDir`) search files natively; in WebAssembly they return `ToposError::Files`. `boltffi.toml` was made with `boltffi init`. `ToposTranslations` and the `*_with_translations` methods (`translations.rs`). Feature `markup` (default): `ToposBook` reads a book's USX/OSIS (`chapterVerses()` gives its own verse counts, from `topos-bible-markup`'s `verses::chapter_verses`) and renders passages as HTML or text (the Obsidian plugin shows verses with it; the text comes from the caller). Build with `boltffi pack python`, or `npm install && npm run pack:wasm` for WASM. Its README and `examples/` (Node, Python) are verified; the Swift and Kotlin snippets are not.

## Commands

- `cargo test`. CI also runs `cargo fmt --check`, `cargo clippy --all-targets` with `-D warnings` on stable, and `cargo test -p topos-bible-formats --features pdf`.
- `cargo bench -p topos-bible` (Criterion), `cd fuzz && cargo +nightly fuzz run search`.
- Use `rg` and `fd`, not `grep` and `find`.

## Conventions and lessons

- Completion logic lives only in the library (`BibleMatcher::complete`): which books a word offers, narrowing by the typed number, whether the segment being typed is a verse (`Resolver::next_verse_chapter`, the same rule as search), and leaving out completions that change nothing. Front ends only add presentation and typing preferences. Add completion behavior to `crates/topos-lib/tests/cases/complete.txt`; the library, CLI, FFI, LSP, and the Obsidian plugin (its own repository) each run it.
- Add search behavior changes to `crates/topos-lib/tests/cases/search.txt` (`input => Ref | Ref`; `?` marks a known failure; `\n` is a line break). Expected values are `Segments`' display form, which is designed to parse back to the same passage.
- The interpretation rules live only in the resolver: chapters until a verse appears, `;` resets to chapters, single-chapter books, `ff`, Roman numerals only where a chapter goes, and a `.`-part fallback.
- False-positive rules (book candidates, `FoundPassage::find`): candidates don't consume the chapter, ambiguous abbreviations (marked `ambiguous` in `default_books.json`) need an explicit verse, there are no candidates inside runs of 64+ characters without whitespace, a book glued to its chapter needs a verse, and the book name's casing must be plausible. Test new rules against a real corpus (diff old and new output), not only unit tests.
- Quantities aren't references: a reference that runs into `5%`, `39pt` or `1.5°` is dropped. Ambiguous abbreviations need a `:` verse (or a `.` verse after `Is.`).
- Performance: keep the candidate regex on `find_iter` with ASCII `(?-u:\b)`. Capture groups or Unicode `\b` made it about 30× slower.
- Parse a single reference with `BibleData::parse`, which resolves with versification like search (`Jude 5` is verse 5; `John 3:99` is `None`); `Books::parse` doesn't know chapter counts. Filters and the FFI's `parse` use it.
- Line and column positions are 1-based, with byte, char, and UTF-16 columns (`LineIndex`). Byte offsets are the source of truth.
- Errors: `ToposError` in the core, `FormatError` in formats. No `unwrap` in library code.
- `Cargo.lock` is gitignored. Commit messages end with a `Co-Authored-By` line.
